# 2026-11-17 视频故障与公开元数据复核

## 结论与证据

客户账户出现 6 次视频失败，涉及 Seedance 2.0、Fast、2.5 和 Muse。任务均在上游提交阶段收到明确 4xx 后失败，未绑定上游任务 ID，最终 quota 为 0。客户端收到的是本站持久化队列的任务 ID，不是上游已受理的证明。旧实现清除了提交载荷且只保留通用拒绝提示，因此没有每次失败的原始请求体和完整上游拒绝原因。

所有这些任务的计费快照均未识别 resolution，记录为 default。受控对照复现：直接发送 `size: "1280x720"` 时，上游返回 400 / unsupported_parameter，将 `1280x720` 当作 resolution 拒绝；用 `resolution: "720p"`、`aspect_ratio: "16:9"` 时正常受理。这个复现与客户“换尺寸仍失败”的表现及缺少 resolution 的记录吻合，但不把未保留的历史请求体当作已知事实。

同一视频密钥在直连上游和本站 Fast 480p 测试中均生成成功，因此“余额耗尽或所有视频模型全面不可用”不符合本轮实测。未重放客户的原生成任务，所有付费验证使用管理员账户的独立小任务。

## 本次修复

- 视频 size 参数兼容常见像素尺寸（包括横竖版 1280×720、1920×1080）、分辨率枚举及宽高比，统一规范化为 resolution / aspect_ratio，并从上游请求中移除 size。
- 请求发送与计费使用同一个规范化结果，避免 size 对应 720p 而预扣落入 default。size 与显式参数冲突、未知像素尺寸直接在排队/扣费前返回 400。
- 元数据中的 size 同样经过规范化。未知对象属性名不会误当成像素尺寸表条目。
- 上游 unsupported_parameter 失败显示明确的规格检查提示，不透出原始上游错误文本；运维日志记录本站任务 ID、渠道 ID 和 HTTP 状态，不记录提示词或密钥。
- 通用任务查询及普通用户任务列表的公开平台值为 media。原内部平台标识保留在管理与路由层，普通用户按 media 筛选仍可查询原任务。
- 公开价格目录的插件标识/名称为 media / Allin Media；在响应边界复制后转换，管理端缓存和原定价不受影响。前端价格展示兼容公开标识。
- 公开版本号使用 allin.media.6。已验证 /api/status、/api/pricing、/api/pricing_new、/v1/models、/v1/tasks/{id} 的相关返回不再出现上游平台名称。管理员诊断、服务器内部标识和上游媒体临时地址仍按实际接口保留。

## Studio 对照

Studio Seedance 直连同一上游地址、使用相同视频密钥，传入的是正确的 resolution / aspect_ratio：

- Fast：本轮返回 provider task mapping failed。
- Mini：成功生成 480p 视频，文件可下载和解码；返回 cloudStorageStatus=save_failed，说明自动持久化另有异常。
- 特价 Muse：返回供应商页面加载超时，未出现聊天输入框，并明确表示未确认会话失效。

Studio 本轮并非全正常或全失败。存在独立的上游映射/页面加载与存储问题，这些与本站 size 参数兼容缺陷分别记录；没有将它们解释成已证实的余额或风控问题。
